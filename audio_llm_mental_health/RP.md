# Diagnosing and Mitigating Modality Collapse in Audio-LLMs: A Controlled Study Across Naturally-Coupled and Synthetically-Decoupled Speech

## Problem

Audio-LLMs (Qwen2-Audio-class) are built on text-native LLMs, so their latent space is biased toward textual semantics; in emotion-from-speech tasks they ride the transcript and underuse the acoustic channel — *modality collapse*. That this collapse has **both data-level and architecture-level origins is now well established**: noisy features of one modality entangle with the predictive features of another in shared fusion neurons and get masked [arXiv 2505.22483, "A Closer Look at Multimodal Representation Collapse," Chaudhuri, Dutta, Bui & Georgescu, ICML 2025 Spotlight — confirmed via the arXiv abstract and ICML poster page], while on the architecture side the modal information is *not* lost in the encoder (speaker identity and emotion remain linearly decodable) — the decoder simply exploits only the text-aligned directions and treats the rest as noise, a bottleneck shown to be governed by the decoder's training objective / scoring rule (a generalized-mutual-information limit) rather than by the projection or adapter choice [arXiv 2602.23136, "Modality Collapse as Mismatched Decoding: Information-Theoretic Limits of Multimodal LLMs," Jayadev Billa, submitted 2026-02-26 — confirmed via the arXiv abstract page]. The same work reports that changing the training objective (e.g. adding an emotion task) raises modal accessibility (+7.5% [cite — VERIFY: exact figure; titles/authors/venue/core claims for both papers above are confirmed, but this specific number was not surfaced by a search summary and needs a direct read of the paper text]), confirming the objective — not the architecture per se — gates which modalities get used.

What remains **unaddressed is whether these two families of intervention are equivalent**. Data-level interventions (removing the transcript shortcut) and objective/architecture-level interventions (a dedicated emotion path with a disentanglement objective) have each been shown to reduce collapse *in isolation*, but no study compares them on a single ruler with coupling as the only manipulated variable. Whether removing the cause at the data level and counteracting it at the objective level reduce collapse by the same amount is an open question with no published systematic control.

## Core Finding (already obtained)

A LoRA-fine-tuned `Qwen2-Audio-7B-Instruct` baseline (MELD; audio + transcript → CoT + emotion label, 9,988 utterances) exhibits the expected collapse. On a 200-row dev sample (greedy decoding): audio + transcript = 0.645; **silence** + transcript = 0.670; audio + placeholder transcript = 0.515 (majority baseline 0.370). Removing audio raises accuracy; a donor-clip swap changes the predicted label to the donor's emotion only 2/15 times (chance for 7-way). Diagnosed proximate cause: the CoT supervision target is a deterministic function of the gold label, giving gradient descent no reason to use the audio encoder once the transcript offers an easier path. This baseline is the fixed measurement instrument; the same ablation is re-run under every condition below.

The first re-run of this ruler — the supervision-level intervention named below (acoustic-grounded CoT targets via `extract_acoustic_priors.py`'s corpus-tertile pitch/loudness-variance/pace buckets, plus `text_mask_prob=0.3` transcript dropout at train time) — already shows movement. Same 200-row dev sample, same greedy decoding: audio + transcript = 0.635 (127/200); silence + transcript = 0.600 (120/200); delta (audio − silence) = **+0.035**, flipping the sign of the collapsed baseline (where audio *hurt*, 0.645 vs 0.670). Row-level, real audio was needed for the right label on 17/200 rows (correct → wrong when silenced), against 10/200 the other way. Donor-swap tracking, on a fixed, recorded 15-row index set (`228,51,563,501,457,285,209,178,864,65,61,191,447,476,1034`, seeded) rose to 7/15, against the collapsed baseline's 2/15 chance-level rate (exact binomial test vs. the chance null p=1/7: P(X≥7 | n=15) ≈ 0.003). Collapse is reduced, not eliminated: under silence the model still retreats toward the majority class (neutral recall 0.892 → 0.973), and anger/surprise/sadness recall drops measurably without audio (e.g. surprise 0.556 → 0.296) — the partial-reduction outcome the Success Criterion below names as valid. Caveat: the swap indices are a newly-recorded fixed set, not the same rows as the collapsed baseline's unrecorded 2/15, so this is a rate-to-rate, not row-identical, comparison.

The data-level intervention named in Approach point 2 — ESD as the primary decoupling corpus — was run first under the plain (un-fixed, templated-CoT) regime (`configs/train_config_esd_plain.yaml`: `build_synthetic_cot_target`, `text_mask_prob=0.0` — the same un-fixed supervision diagnosed as the proximate cause of the MELD collapse above, with ESD's data-level decoupling as the only change), 3 epochs, LoRA adapter at `outputs/esd_lora_plain/final`. On a 200-row dev sample (`scripts/eval_accuracy.py`, default seed=42): accuracy 0.985 (197/200) against a 0.225 majority baseline ('sadness'), per-class recall 0.952-1.000 across all 5 classes, predictions spread roughly evenly across all 5 labels (33-45 each, no class collapse). `scripts/audio_ablation.py` on a 100-row random sample (`random.Random(42).sample(range(1750), 100)` over `data/esd_dev_manifest.jsonl`): silence changed the label in 83/100 rows — the 17 unchanged are exactly the rows whose original (audio-present) prediction was already 'neutral', the silence condition's universal fallback, so effectively 100% of non-neutral predictions depended on the audio; donor-swap changed the label in 100/100 rows, and the swapped label matched the donor clip's true emotion in 100/100 — a far stronger grounding signal than either the collapsed MELD baseline (2/15, chance-level) or the supervision-fixed MELD rerun (7/15, p≈0.003 vs. chance). This was achieved by the data-level intervention alone: ESD's transcript is identical across all 5 emotions by construction, so the same templated, label-derived CoT target responsible for MELD's collapse offers no shortcut here, and the model was forced into — and fully learned — genuine audio grounding without the supervision-level fix (acoustic-grounded CoT / text masking) MELD needed. This is the first direct evidence on the three-tier data gradient (Approach point 2) that data-level decoupling alone, with no objective/architecture-level change, can fully resolve (not merely reduce, per the donor-swap-tracking ruler) the measured collapse — at least for this corpus's specific form of decoupling (uninformative-but-present text). Whether the acoustic-grounded ESD run (`configs/train_config_esd.yaml`) adds anything on top of this near-ceiling result, and whether the same data-level effect holds on LIME Part B's stricter no-transcript-at-all decoupling, are the next two re-runs of this ruler.

## Hypothesis

Modality collapse is gated by the presence of a transcript shortcut and by the decoder's training objective. Removing the shortcut at the data level — either by keeping the text present but uninformative about the label (a lexically-identical, multi-emotion corpus) or by removing it altogether (no transcript at all) — and counteracting it at the objective/architecture level (a dedicated emotion encoder with a disentanglement objective) are *distinct* mechanisms whose effects can be measured on a single, fixed ruler. Holding language constant, a coupled vs. decoupled comparison should reveal how much of the collapse is data-attributable vs. architecture-correctable.

## Approach: interventions measured on one ruler

The silence-vs-audio delta (and conflict-subset accuracy) is the fixed ruler across all conditions.

1. **Architecture/objective-level.** Add an emotion-centric encoder (Emotion2Vec / HuBERT) as a second tower beside the Whisper-style semantic path, with a modality-specific adapter and an orthogonality / disparity loss forcing the emotion tower to carry signal the semantic tower does not. Adapts the dual-encoder design of Zhang et al. (I2R/A\*STAR 2025) and the disentanglement losses of Chang et al. (IEEE JBHI 2026) to an audio-LLM.
2. **Data-level, a three-tier gradient.** Rather than a single coupled-vs-decoupled pair, the data-level intervention holds the silence-vs-audio ruler fixed across three corpora that vary only in how informative the transcript is about the label, from fully predictive to entirely absent:
   - **MELD** (coupled, the baseline above): transcript present and predictive — the shortcut this whole study is about.
   - **ESD** (primary decoupling condition). Kun Zhou, Berrak Sisman, Rui Liu, Haizhou Li (NUS/SUTD), "Emotional Voice Conversion: Theory, Databases and ESD," arXiv:2105.14762 (later in *Speech Communication*). 10 English + 10 Mandarin speakers, 350 parallel sentences read under each of 5 emotions (neutral/happy/angry/sad/surprise), ~17.5k English utterances; license-gated, research-only (`zhoukun@u.nus.edu`), downloaded directly via the Google Drive link in the dataset's own GitHub README (`HLTSingapore/Emotional-Speech-Data`), not via LIME's re-annotated version (LIME's re-annotation scripts are not public; see "Open premises"). Confirmed by direct read of the per-speaker transcript files (not just the paper's "350 parallel" prose): the *same exact sentence text* recurs under all 5 emotion labels for a given speaker, so the transcript is present but carries zero label signal by construction. Because the transcript is present, both halves of the ruler (audio+transcript and silence+transcript) can be run on ESD, exactly mirroring the MELD ablation — this is the property LIME Part B's public release claims but doesn't deliver (see below), and why ESD is the primary data-level corpus. ESD is run under both the plain (templated-CoT) and acoustic-grounded regimes used on MELD: the plain run isolates whether removing the transcript shortcut *at the data level alone* — leaving the CoT-from-gold-label shortcut diagnosed in the Core Finding otherwise untouched — already changes the silence-vs-audio delta, before the supervision-level fix is layered on top.
   - **LIME-Core Part B** (strictest supplement). English; `zhaoxiaoxian/LIME-440K_CogAudio-LLM` on Hugging Face; introduced in "Beyond Semantic Dominance: Cognitive Affective Reasoning and Empathetic Response Alignment in Audio Language Models" (Zhao, Wang, Tian, Hu, Zhang, Xie; ASLP@NPU; arXiv:2606.06940, accepted at INTERSPEECH 2026 per the arXiv listing). The paper frames Part B as "lexically-identical, multi-emotion" text, but the public release's `text` field is `null` for all ~96,000 records (see "Open premises"), so in practice it is a pure audio-only corpus with no transcript to leak at all — stricter decoupling than ESD's, but only the audio-only half of the ruler can be run on it; there is no transcript-present condition to compare against.

(A lighter supervision-level intervention — feature-anchored CoT targets computed from real acoustics plus transcript-masking — is already implemented and measured; see Core Finding above.)

## The controlled comparison (contribution)

The same dual-encoder + disentanglement architecture is run on **MELD** (natural speech, text-acoustic *coupled*, transcript shortcut available), **ESD** (acted speech, *decoupled* but transcript present — primary condition), and **LIME Part B** (synthetic speech, *decoupled*, no transcript at all — strictest supplementary condition) — all English, so language is held constant and coupling is the only manipulated variable across the gradient. This **directly tests the equivalence of data-level vs. objective-level interventions**: when the transcript shortcut is removed at the data level (in either of its two forms) versus counteracted at the architecture/objective level, does modality collapse change by the same amount, and does the *form* of data-level decoupling (uninformative-but-present vs. absent) matter? It supplies the systematic control that the cited works — each operating within a single data regime and testing one intervention family in isolation — do not provide.

## Open premises to verify (honest)

- LIME Part B's decoupling was originally taken from the paper as "lexically-identical text, multiple emotions"; a JSON-only probe (`scripts/probe_lime_partB.py`) was run instead to confirm this by direct read rather than by trusting the paper's prose. The Part A/B utterance counts (223,884 / 96,000) are confirmed via a direct read of the dataset card (`zhaoxiaoxian/LIME-440K_CogAudio-LLM`). The repo layout and field names are confirmed by a direct `HfApi.list_repo_files` + `json.load()` read (not the paper's prose, not the HF `datasets` auto-loader, which mis-parses this repo): annotations live under `PartA_json_CN/*.json` (Chinese) and `PartB_json_EN/*.json` (English, the split this project uses) as one JSON dict per file, keyed by utterance id, with fields `text`, `emotion`, `scenario`, `group`, `wav_path`; audio ships as one `PartB_wav_en.tar.gz` archive rather than per-row. The "both English" premise for the coupled-vs-decoupled comparison holds, since Part A/B are segregated by folder rather than mixed in one split.
  **Revised premise (probe result, exhaustive):** Part B's `text` field is `null` in 100% of its ~96,000 records in this public release — confirmed by scanning every one of the 32 `PartB_json_EN/*.json` files (`0 usable records, missing-field skips: 96000` when `text` was required) and by a full raw dump of one 3,000-record file showing every entry with `"text": null`. The `group`/`scenario`/`emotion`/`wav_path` structure is intact regardless: each `group` still contains multiple records with different emotions sharing one scenario, so LIME's "shared cluster, multiple emotions" design holds structurally even though the transcript itself is absent. This project therefore uses Part B as a **pure audio-only decoupling corpus** rather than a lexically-identical-text one: `scripts/build_lime_manifest.py` writes `transcript: ""` for these rows (no longer skipping them as missing-field), and `data/meld_dataset.py`'s `MELDDataset` forces `include_transcript=False` whenever a row's transcript is empty, independent of `text_mask_prob`. This is a strictly stronger decoupling condition than the original premise — there is no transcript at all to leak, lexically or otherwise, rather than a same-but-uninformative one. The punctuation-level nuance noted in an earlier draft of this bullet (e.g. the same sentence ending in "？！" for surprise, "......" for fear, "！" for happy) was observed in **Part A (Chinese)** samples, not Part B, and is reported here only as a caveat about Part A should it ever be used; it does not apply to the English Part B split this project trains/evals on, since Part B has no text to exhibit such a nuance in.
- **ESD's parallel-text structure**, confirmed by direct read of the extracted release (not the paper's prose alone): each speaker directory has one `<speaker_id>.txt` (tab-separated `utt_id`, `text`, `EmotionLabel`, 1,750 = 350×5 lines) plus 5 per-emotion `.wav` subfolders (`Neutral`/`Angry`/`Happy`/`Sad`/`Surprise`, 350 files each, matching the `.txt` labels exactly). For English speaker `0011`, utt ids `0011_000001` / `_000351` / `_000701` / `_001051` / `_001401` (an offset of exactly 350, the block size) all carry the literal text `"The nine the eggs, I keep."` under `Neutral`/`Angry`/`Happy`/`Sad`/`Surprise` respectively — the lexically-identical-text claim holds exactly, at least for this sampled case. Speakers `0001`–`0010` are Mandarin, `0011`–`0020` English (confirmed by reading `0001.txt`'s Chinese text vs. `0011.txt`'s English text), matching the dataset card. Audio is 16kHz mono PCM_16 already (confirmed via `soundfile.info` on a sampled file), so `scripts/build_esd_manifest.py`'s resample step is a no-op in practice but is kept as a defensive fallback. Release ships flat per-emotion folders with no train/evaluation/test subfolders (despite some secondary documentation describing a three-way split) — `build_esd_manifest.py` does its own group-level split, grouping by `(speaker, sentence-index)` derived from the utt-id numbering, to keep a sentence's 5 emotion-variants from spanning train and dev.
- LIME is TTS-synthesized; ESD is studio-recorded but acted/read speech, not spontaneous — in both cases a residual synthetic-or-acted vs. spontaneous prosody gap relative to MELD's natural speech is a known limitation, reported rather than hidden.
- The two framing citations (arXiv 2505.22483, 2602.23136) are now corroborated by independent search of their arXiv/ICML listing pages — titles, authors, venue, and core claims all match the prose above, no longer flagged. The one open item is the specific **+7.5% modal-accessibility** figure attributed to arXiv 2602.23136: a search summary did not surface that exact number, so it still needs a direct read of the paper text before submission. (The LIME-440K citation, arXiv 2606.06940, is confirmed directly from the arXiv listing page itself, author list and INTERSPEECH 2026 acceptance included.)

## Expected Contribution

Not beating SOTA on emotion accuracy. Rather: a clean, reproducible, single-GPU study that (1) measures modality collapse on a fixed ablation ruler, (2) applies mechanistically distinct interventions, and (3) compares coupled vs. decoupled speech under one language to directly test whether data-level and objective-level interventions are equivalent — a control absent from prior work, each of which establishes one intervention in isolation. Every claim ties to a re-runnable ablation rather than to the cited papers.

## Success Criterion

For each condition, re-running the silence-vs-audio ablation yields a measurable, reported shift; the coupled-vs-decoupled contrast yields an interpretable difference in collapse magnitude. A partial outcome on natural MELD (collapse reduced, not eliminated) is a valid result and the stated motivation for data-level decoupling.

## Future Work

The same evidence-grounded CoT mechanism — a model that states the acoustic cues behind its emotion judgment — could serve as a case-level interpretable layer atop existing classical pipelines in clinical speech assessment, complementing rather than competing with feature-based methods. Pursuing this in a UHR / clinical setting would require not only data access and ethics approval but genuine domain grounding in the clinical construct, which is a prerequisite to be built, not an asset already in hand. Out of scope here.

## Environment

All training/inference on the GPU cluster (H100). Login/transfer node for downloads (compute nodes offline). `$HOME` (`/`) is a small, easily-filled 58 GB partition — confirmed the hard way when it hit 100%/0 available mid-download. All large data (LIME's 52 GB audio, ESD's ~2.45 GB, HF/conda/pip caches via `HF_HOME`) goes on the shared `/data` volume (3+ TB, confirmed via `df -h`) instead, e.g. `/data/user_dirs/$USER/`; there is no `$SCRATCH` env var set on this cluster, despite some earlier guidance assuming one.

The per-student GPU allocation turned out to be a MIG (Multi-Instance GPU) slice, not the full card: `nvidia-smi` shows the physical device as an `H100 80GB HBM3` with MIG enabled, partitioned into seven `1g.10gb` instances (~9.75 GiB each), and the student's job is bound to exactly one such slice with no contention from other processes ("No running processes found" on the others). Qwen2-Audio-7B-Instruct (~8.2B params) needs ~16 GB just for bf16 weights, so `Qwen2AudioForConditionalGeneration.from_pretrained(..., torch_dtype=torch.bfloat16)` OOMs inside `from_pretrained` itself, before any batch-size/gradient-accumulation tuning or training data is even touched — confirmed by identical `torch.OutOfMemoryError` traces on both the ESD smoke test and the full ESD plain-baseline run, both failing at the same "Loading weights" checkpoint. Fix: load the base model 4-bit-quantized (QLoRA-style: `BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_use_double_quant=True, bnb_4bit_compute_dtype=torch.bfloat16)`), bringing base weights to ~4 GB and leaving headroom for activations and the LoRA adapter within the 9.75 GiB slice. Centralized in `data/model_loading.py::load_base_model`, used by all five scripts that load the base model.

A second, narrower OOM showed up one step later, only in `train_lora.py`: `peft.prepare_model_for_kbit_training()` (the standard pre-LoRA call on a quantized base) casts every bf16/fp16 param that ISN'T 4-bit-quantized -- embeddings, lm_head, norms -- to fp32, and that cast itself OOM'd (~8.5 GiB already in use right after the 4-bit load, then a 2.38 GiB fp32-upcast allocation that didn't fit in the remaining ~1.26 GiB). Since the base model is frozen regardless (LoRA only trains the adapter) and `bnb_4bit_compute_dtype=bfloat16` already runs every matmul in bf16 independent of storage dtype, the fp32 upcast buys stability headroom this slice can't afford and doesn't need. Replaced with `data/model_loading.py::prepare_for_qlora_training`, which keeps the two things that matter under this memory budget -- `enable_input_require_grads()` and `gradient_checkpointing_enable()` -- without the upcast. Confirmed working end-to-end on the real 9.75 GiB slice: the ESD smoke test (`train_config_esd_smoke.yaml`) completed all 10 steps of its single epoch with loss falling 3.59 -> 1.41, no OOM at load, prepare, or any training step.

Open question, not yet resolved: the MELD Core Finding numbers reported above were produced by an earlier `train_lora.py` that loaded the base model in plain bf16, with no quantization. Whether that run used this same 9.75 GiB MIG slice (which seems impossible under bf16 at this model size) or a different/larger allocation is unconfirmed. If it was the same slice class, the original numbers and any new 4-bit-quantized runs (ESD, MELD reruns) are on different ruler and not directly comparable; this needs to be checked before drawing cross-run conclusions.

The wall-clock cost of fitting on a `1g.10gb` slice is structural, not a misconfiguration: MIG partitions compute (SM count) and memory bandwidth proportionally to memory capacity, so this slice has roughly 1/7 of the card's compute regardless of how much of its 9.75 GiB is actually used. On top of that, the two OOM fixes above are both time-for-memory trades that add real overhead beyond the 1/7 split: `gradient_checkpointing_enable()` recomputes the forward pass during backward instead of caching activations (the dominant slowdown), and 4-bit weights must be dequantized to bf16 before every matmul. `per_device_train_batch_size: 2` also leaves per-step GPU parallelism underused. None of these are tunable away without more memory headroom than this slice has (~2 GiB free during the ESD plain run at 7952/9984 MiB used) — there isn't room to disable checkpointing, and raising `gradient_accumulation_steps` doesn't help wall-clock since it changes how often `optimizer.step()` runs, not the per-micro-batch compute (the actual fix, raising `per_device_train_batch_size`, would need more memory, the opposite of what's available). TF32 (`torch.backends.cuda.matmul.allow_tf32` / `cudnn.allow_tf32`, set at import in `data/model_loading.py`) is the one free lever — no memory cost, since the 4-bit matmuls already run in `bnb_4bit_compute_dtype=bf16` regardless and TF32 only affects the remaining fp32 paths (LoRA adapter, unquantized embeddings/lm_head/norms).

Every `train_lora.py` run now writes `<output_dir>/run_metadata.jsonl` (one line per process launch: resolved config, LoRA config, resume source, start time) and `<output_dir>/metrics.jsonl` (one line per `logging_steps` interval: step, epoch, loss, lr, wall-clock elapsed) — durable records of what a run was and how it went, independent of terminal/tmux scrollback. Added after a run produced no record of its own hyperparameters or loss trajectory once the shell history scrolled past it.
