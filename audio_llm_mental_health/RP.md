# Diagnosing and Mitigating Modality Collapse in Audio-LLMs: A Controlled Study Across Naturally-Coupled and Synthetically-Decoupled Speech

## Problem

Audio-LLMs (Qwen2-Audio-class) are built on text-native LLMs, so their latent space is biased toward textual semantics; in emotion-from-speech tasks they ride the transcript and underuse the acoustic channel — *modality collapse*. That this collapse has **both data-level and architecture-level origins is now well established**: noisy features of one modality entangle with the predictive features of another in shared fusion neurons and get masked [arXiv 2505.22483, "A Closer Look at Multimodal Representation Collapse," Chaudhuri, Dutta, Bui & Georgescu, ICML 2025 Spotlight — confirmed via the arXiv abstract and ICML poster page], while on the architecture side the modal information is *not* lost in the encoder (speaker identity and emotion remain linearly decodable) — the decoder simply exploits only the text-aligned directions and treats the rest as noise, a bottleneck shown to be governed by the decoder's training objective / scoring rule (a generalized-mutual-information limit) rather than by the projection or adapter choice [arXiv 2602.23136, "Modality Collapse as Mismatched Decoding: Information-Theoretic Limits of Multimodal LLMs," Jayadev Billa, submitted 2026-02-26 — confirmed via the arXiv abstract page]. The same work reports that changing the training objective (e.g. adding an emotion task) raises modal accessibility (+7.5% [cite — VERIFY: exact figure; titles/authors/venue/core claims for both papers above are confirmed, but this specific number was not surfaced by a search summary and needs a direct read of the paper text]), confirming the objective — not the architecture per se — gates which modalities get used.

What remains **unaddressed is whether these two families of intervention are equivalent**. Data-level interventions (removing the transcript shortcut) and objective/architecture-level interventions (a dedicated emotion path with a disentanglement objective) have each been shown to reduce collapse *in isolation*, but no study compares them on a single ruler with coupling as the only manipulated variable. Whether removing the cause at the data level and counteracting it at the objective level reduce collapse by the same amount is an open question with no published systematic control.

## Core Finding (already obtained)

A LoRA-fine-tuned `Qwen2-Audio-7B-Instruct` baseline (MELD; audio + transcript → CoT + emotion label, 9,988 utterances) exhibits the expected collapse. On a 200-row dev sample (greedy decoding): audio + transcript = 0.645; **silence** + transcript = 0.670; audio + placeholder transcript = 0.515 (majority baseline 0.370). Removing audio raises accuracy; a donor-clip swap changes the predicted label to the donor's emotion only 2/15 times (chance for 7-way). Diagnosed proximate cause: the CoT supervision target is a deterministic function of the gold label, giving gradient descent no reason to use the audio encoder once the transcript offers an easier path. This baseline is the fixed measurement instrument; the same ablation is re-run under every condition below.

The first re-run of this ruler — the supervision-level intervention named below (acoustic-grounded CoT targets via `extract_acoustic_priors.py`'s corpus-tertile pitch/loudness-variance/pace buckets, plus `text_mask_prob=0.3` transcript dropout at train time) — already shows movement. Same 200-row dev sample, same greedy decoding: audio + transcript = 0.635 (127/200); silence + transcript = 0.600 (120/200); delta (audio − silence) = **+0.035**, flipping the sign of the collapsed baseline (where audio *hurt*, 0.645 vs 0.670). Row-level, real audio was needed for the right label on 17/200 rows (correct → wrong when silenced), against 10/200 the other way. Donor-swap tracking, on a fixed, recorded 15-row index set (`228,51,563,501,457,285,209,178,864,65,61,191,447,476,1034`, seeded) rose to 7/15, against the collapsed baseline's 2/15 chance-level rate (exact binomial test vs. the chance null p=1/7: P(X≥7 | n=15) = Σ_{k=7}^{15} C(15,k)(1/7)^k(6/7)^{15−k} ≈ 0.0027). Collapse is reduced, not eliminated: under silence the model still retreats toward the majority class (neutral recall 0.892 → 0.973), and anger/surprise/sadness recall drops measurably without audio (e.g. surprise 0.556 → 0.296) — the partial-reduction outcome the Success Criterion below names as valid. Caveat: the swap indices are a newly-recorded fixed set, not the same rows as the collapsed baseline's unrecorded 2/15, so this is a rate-to-rate, not row-identical, comparison.

The data-level intervention named in Approach point 2 — ESD as the primary decoupling corpus — was run first under the plain (un-fixed, templated-CoT) regime (`configs/train_config_esd_plain.yaml`: `build_synthetic_cot_target`, `text_mask_prob=0.0` — the same un-fixed supervision diagnosed as the proximate cause of the MELD collapse above, with ESD's data-level decoupling as the only change), 3 epochs, LoRA adapter at `outputs/esd_lora_plain/final`. On a 200-row dev sample (`scripts/eval_accuracy.py`, default seed=42): accuracy 0.985 (197/200) against a 0.225 majority baseline ('sadness'), per-class recall 0.952-1.000 across all 5 classes, predictions spread roughly evenly across all 5 labels (33-45 each, no class collapse). `scripts/audio_ablation.py` on a 100-row random sample (`random.Random(42).sample(range(1750), 100)` over `data/esd_dev_manifest.jsonl`): silence changed the label in 83/100 rows — the 17 unchanged are exactly the rows whose original (audio-present) prediction was already 'neutral', the silence condition's universal fallback, so effectively 100% of non-neutral predictions depended on the audio; donor-swap changed the label in 100/100 rows, and the swapped label matched the donor clip's true emotion in 100/100 — a far stronger grounding signal than either the collapsed MELD baseline (2/15, chance-level) or the supervision-fixed MELD rerun (7/15, p≈0.003 vs. chance). This was achieved by the data-level intervention alone: ESD's transcript is identical across all 5 emotions by construction, so the same templated, label-derived CoT target responsible for MELD's collapse offers no shortcut here, and the model was forced into — and fully learned — genuine audio grounding without the supervision-level fix (acoustic-grounded CoT / text masking) MELD needed. On the donor-swap-tracking ruler this is a full, not partial, resolution of the collapse — but the causal attribution is **confounded by acoustic signal strength** and must not be over-read. ESD is parallel *acted* speech: the five emotions are deliberately, exaggeratedly performed over identical text, so the acoustic emotion cue is unusually loud and clean — the opposite of MELD's natural, subtle, semantically-entangled prosody. The ESD condition therefore changes *two* variables at once relative to MELD (the transcript shortcut is removed **and** the acoustic signal is far stronger), and this run alone cannot separate "the model grounds because the text shortcut is gone" from "the model grounds because the audio is too loud to ignore." The 100/100-vs-7/15 gap between ESD-plain and the supervision-fixed MELD rerun may reflect decoupling *degree*, acoustic *strength*, or both. This confound is structural to the corpus lineup, not specific to ESD: every decoupled corpus on hand has non-natural acoustics (ESD acted; LIME TTS-synthesized, if anything *more* stylized), while the only natural-acoustic corpus (MELD) is the coupled one — so no off-the-shelf corpus swap isolates the variable. The clean isolation is a **within-MELD** ablation that holds acoustic strength fixed (natural/weak) and removes only the transcript: train MELD with `text_mask_prob=1.0` under the same plain templated-CoT regime (the missing "decoupled + weak-acoustic" cell). If that also grounds, the decoupling effect generalizes off ESD's loud acoustics; if it stays near the collapsed/7-15 level, ESD's 100/100 was carried by acoustic strength, not by decoupling per se. Until that cell is run, the ESD result stands as "data-level decoupling is *sufficient* for full grounding on a strong-acoustic decoupled corpus," not as "removing the text shortcut is *what* produced the grounding." Whether the acoustic-grounded ESD run (`configs/train_config_esd.yaml`) adds anything on top of this near-ceiling result, and whether the same data-level effect holds on LIME Part B's stricter no-transcript-at-all decoupling, are lower-priority re-runs of this ruler — the `text_mask_prob=1.0` MELD cell, which actually breaks the confound, comes first.

A first, cheap pass at this confound was run before committing to the `text_mask_prob=1.0` training cell, using a split rather than a retrain. `extract_acoustic_priors.py`'s per-clip pitch/loudness-variance/pace tertile buckets were applied to the MELD **dev** manifest itself (not just used to build CoT targets) and `scripts/split_by_acoustic_strength.py` split it into a high-acoustic-strength subset (409 rows, composite high>low across the three buckets) and a low-acoustic-strength subset (385 rows; 314 dropped as all-mid/tied). The split immediately surfaces a real confound in the proxy itself: the high subset's emotion mix skews toward anger/joy/surprise (neutral 32.3%) while the low subset skews toward neutral/sadness (neutral 51.2%), so total accuracy is not directly comparable between the two — the low subset's higher headline accuracy is partly just more neutral, the model's silence-fallback class. Reading per-class recall instead, isolated from that skew, for the two classes the 4-bit baseline actually uses audio for: anger's audio-vs-silence recall gain is nearly identical between subsets (+0.178 high vs. +0.157 low), and sadness's gain is, if anything, *larger* in the low-acoustic subset (+0.125 high vs. +0.204 low). Both subsets remain net-collapsed overall (total audio-minus-silence accuracy delta −0.002 high, −0.011 low), so this compares two still-collapsed regimes to each other, not a collapsed-vs-fixed pair. If acoustic loudness were the active ingredient in ESD's full-grounding result, the high subset should show a materially larger audio benefit than the low subset; it does not. This is observational, not causal, evidence — weakened further by the proxy's own failure mode (sad speech is acoustically quiet by construction, so it lands in the "low" bucket despite carrying real audio-detectable emotion signal, which is exactly the +0.204 result above) — but it shifts the prior against acoustic-strength-as-confound *before* the `text_mask_prob=1.0` training run, which remains the causal experiment that actually settles the question.

The `text_mask_prob=1.0` MELD cell — the causal experiment that actually isolates decoupling from acoustic strength, rather than just shifting the prior on it — was then run (`configs/train_config_meld_textmask1_4bit.yaml`: 4-bit QLoRA, plain templated CoT, otherwise identical to the 4-bit MELD baseline), and evaluated under the pinned in-distribution protocol (`--audio-only`, since this model never saw a transcript during training and the with-transcript ruler would be train/test-mismatched for it). Audio-only (real audio, no transcript in the prompt) accuracy: 0.573 (114/199), +0.203 above the 0.370 majority baseline, recall spread across six classes (neutral 0.770, anger 0.452, joy 0.519, surprise 0.481, sadness 0.538, fear 0.222; disgust, n=6, never predicted). Audio-only **with silence**: 0.360 (72/200), −0.010 *below* baseline, recall collapsed almost entirely onto neutral (0.946; every other class ≤0.077, four classes at exactly 0.000) — 191/200 predictions were 'neutral'. Delta (audio-only − silence-only) = **+0.213**, the cleanest version of this ruler run so far: with no transcript in the prompt at all, there is no other channel silence could be leaking the answer through, so the collapse-on-silence / spread-on-audio shapes are attributable to audio alone, not residual signal from a hidden transcript. Donor-swap tracking on the same fixed 15-row index set: **9/15** swap labels matched the donor's emotion (silence changed the label 10/15 times; swap changed it 15/15 times) — far above chance (exact binomial P(X≥9 | n=15, p=1/7) = Σ_{k=9}^{15} C(15,k)(1/7)^k(6/7)^{15−k} ≈ 5.45e-05), above both collapsed baselines (2/15 bf16-plain, 3/15 4-bit-plain — **3/15 is the apples-to-apples comparison point**, same 4-bit QLoRA precision regime as this run; the 2/15 bf16 number differs by precision, not just by `text_mask_prob`) *and* above the supervision-fixed MELD rerun (7/15, acoustic-grounded CoT + `text_mask_prob=0.3`), though still well short of ESD-plain's ceiling (100/100, i.e. 15/15 on this same kind of set).

Tracking and accuracy are **orthogonal claims, not one signal read twice**: donor-swap tracking measures whether the prediction *follows* the audio (grounding — a model could track perfectly on a wrong or trivial acoustic cue and still score 9/15), while accuracy-vs-gold measures whether the audio-derived prediction is *correct* (signal quality — a model could use audio sparingly yet correctly whenever it does). That both moved together here is what makes the reading below solid: tracking rising (9/15, far above chance) shows the model leans on audio more than the collapsed baselines did; accuracy rising (+0.203 over the majority baseline, with recall spread across six classes rather than collapsed) shows that increased reliance is informative, not noise. Either number alone would be weaker evidence — high tracking with baseline-level accuracy would say "grounds on noise," high accuracy with baseline-level tracking would say "right for the wrong (text) reasons" — together they say the model both uses audio more *and* uses it well.

This settles the confound raised above in favor of **decoupling, not loudness**, as the dominant driver: removing the transcript shortcut entirely — even on MELD's naturally weak, subtle acoustics, and even under the cheaper plain (non-acoustic-grounded) CoT target — produces substantially more grounding than either the collapsed baseline or the supervision-level fix achieved, confirming causally what the Route B split could only support observationally. The remaining gap to ESD's ceiling (9/15 vs. 15/15) is a **plausible interpretation, not isolated evidence**, that acoustic strength adds a further boost on top of decoupling: ESD differs from this MELD cell in corpus, acoustic strength, *and* potentially CoT regime, three variables confounded together, so the gap cannot currently be attributed to acoustic strength alone. What is now causal: decoupling alone is sufficient for large, non-chance grounding on weak acoustics. Whether acoustic strength adds anything further on top of that is, for now, a hypothesis carried into Future Work, not a result already obtained. (The absolute accuracy numbers above are not comparable to the with-transcript regimes' 0.645/0.660/0.635 — different prompt, different task framing, per the eval RUNBOOK's instruction; only the audio-vs-silence delta and the per-class recall shape are read across regimes.)

The third and strictest tier of the data-level gradient — LIME Part B, which (per "Open premises" below) ships with `text` null in 100% of its public release and is therefore audio-only by data construction rather than by `text_mask_prob` masking — was run next (`configs/train_config_lime_partB_4bit.yaml`: 4-bit QLoRA, plain templated CoT, a representative 12k-row sample of the ~96k corpus drawn by `build_lime_manifest.py --sample 12000` (seed 42), train/dev split 10,806/1,194 rows). Evaluated under the same pinned in-distribution protocol as the MELD `text_mask_prob=1.0` cell (`--audio-only`, since every row is audio-only by construction, train and eval alike): on a 200-row dev sample (seed 42, greedy), audio-only accuracy = 0.835 (167/200), well above the 0.185 majority baseline. LIME's 200-row dev sample is fairly balanced across its 7 classes (n=23-37 each, unlike MELD's neutral-skewed distribution), so this absolute number is **not** comparable to MELD's/ESD's — only the delta and per-class shape are. Audio-only **with silence**: 0.120 (24/200), *below* the majority baseline, with predictions collapsing 200/200 (100%) onto 'neutral' — the same silence-fallback failure mode seen in the MELD `text_mask_prob=1.0` cell's silence condition (191/200 → neutral), here total rather than near-total. Delta (audio-only − silence-only) = **+0.715**, the largest grounding-signal delta obtained anywhere in this study's gradient so far (vs. MELD `text_mask_prob=1.0`'s +0.213). Donor-swap tracking — the orthogonal grounding measure named two paragraphs above — was then run on that fixed 15-row index set (`scripts/audio_ablation.py --audio-only`, index set `51,61,65,178,191,209,228,285,447,457,476,501,563,864,1116` over `data/lime_dev_manifest.jsonl`, N=1,194): **13/15** swap labels matched the donor clip's emotion (exact binomial P(X≥13 | n=15, p=1/7) ≈ 8.2e-10) — above MELD `text_mask_prob=1.0`'s 9/15, above the supervision-fixed MELD rerun's 7/15, and second only to ESD-plain's ceiling (100/100, i.e. 15/15 on this format). Silence changed the label in 12/15 rows (the other 3 were already 'neutral' pre-silence, so "unchanged" there is the floor, not a grounding failure), and the silence output was 'neutral' in all 15/15 rows — the same total collapse seen in the 200-row accuracy eval, now confirmed row-by-row. Swap changed the label in 15/15 rows. The two grounding measures move together exactly as the orthogonality discipline above requires: tracking (13/15, far above chance, above every cell but ESD's ceiling) shows the model leans on audio more than any corpus but ESD; accuracy (+0.715 delta, the largest in the gradient) shows that reliance is informative rather than noise. Read together with the caveat already flagged in "Open premises": LIME's no-transcript-at-all decoupling produces grounding nearly matching ESD's acted, exaggerated acoustics despite being TTS-synthesized rather than acted — suggestive that decoupling *degree* (none vs. partial-via-masking) matters at least as much as acoustic strength on this ruler, though the corpus/acoustic-strength/synthetic-vs-natural confound from the ESD paragraph above still applies and is not resolved by this result alone.

A complementary, training-free probe was then run to separate two readings of "decoupling raises tracking": **re-arbitration** (the information was already linearly available at every stage; only how the LLM scores/uses it changes) versus **re-representation** (the encoding itself changes under training). `scripts/extract_hidden_states.py` hooks the `multi_modal_projector` forward pass and records, for each row, the mean-pooled hidden state at audio-token positions from three points: the raw `audio_tower` output, the `multi_modal_projector` output, and every one of the 33 LLM decoder layers (since `build_conversation` places audio content before text, and decoding is causal, these audio-position hidden states do not depend on what text follows — so one audio-only prompt is valid across adapters of differing training regime). `scripts/probe_accessibility.py` then fits a linear probe (AUC) at each stage against the gold emotion label. Run on four adapters spanning the donor-swap-tracking gradient established above — `meld_lora_4bit` (tracking 3/15), `meld_lora_textmask1` (9/15), `lime_lora_partB` (13/15), `esd_lora_plain` (normalized to 15/15, i.e. its 100/100) — the headline pattern is that probe AUC at the `audio_tower` stage rises almost as steeply with tracking across this four-point, four-corpus gradient (0.6035 → 0.6167 → 0.9211 → 0.9958) as the final LLM layer does (0.6439 → 0.6807 → 0.9226 → 0.9841): nearly all of the cross-corpus spread is already present before any LLM processing happens, which is the signature of re-arbitration, not re-representation — *if* `audio_tower` were actually frozen across these four runs.

It is not, fully. Re-reading `scripts/train_lora.py:105` (`get_peft_model(model, LoraConfig(**lora_cfg_dict))`, applied to the whole `Qwen2AudioForConditionalGeneration` model, not scoped to `model.language_model`) against `configs/lora_config.yaml`'s `target_modules: [q_proj, k_proj, v_proj, o_proj]`, and against PEFT 0.19.1's actual matching rule (`peft/tuners/tuners_utils.py::check_target_module_exists`: for a list-valued `target_modules`, a module matches iff its full dotted name ends with `.{target_key}` for some target key — a per-component-name suffix match, not a path-scoped one) shows this list does not stay inside the LLM decoder. `Qwen2AudioEncoder`'s attention block (`Qwen2AudioAttention`, copied from Whisper) defines `self.q_proj`, `self.k_proj`, `self.v_proj`, and `self.out_proj` (confirmed by direct read of `transformers/models/qwen2_audio/modeling_qwen2_audio.py`); the LLM decoder (`Qwen2Model`, via `AutoModel.from_config(text_config)`) defines `self.q_proj/k_proj/v_proj/o_proj`. Because three of the four target names (`q_proj`, `k_proj`, `v_proj`) are spelled identically in both stacks, every one of the four trained adapters above has, in fact, applied a rank-16 LoRA delta to `audio_tower`'s query/key/value projections in every encoder layer — only `out_proj` escapes (its component name doesn't match the literal string `o_proj`). So `audio_tower` was never *frozen* in any of these runs; it received roughly 3/4 of the attention-side adapter capacity the LLM decoder did. The one stage in this probe genuinely untouched by training is `multi_modal_projector` (`Qwen2AudioMultiModalProjector.linear`, a single `nn.Linear` not named with any q/k/v/o pattern) — confirmed by the same source read.

This doesn't overturn the finding, but it relocates the clean control point. The `multi_modal_projector` stage shows the same near-monotonic rise with tracking across corpora as `audio_tower` did (0.5844 → 0.6150 → 0.9159 → 0.9975), and since this stage is provably untrained in all four runs, the cross-corpus reading stands on firmer ground than before: most of the AUC spread across MELD/LIME/ESD is intrinsic acoustic-emotion separability (natural/subtle vs. TTS vs. acted/exaggerated), not a training effect, full stop — the prior "frozen audio_tower" framing of this argument was directionally right but rested on an unverified premise. For the one same-corpus, same-acoustic comparison that actually isolates a training effect — `meld_lora_4bit` (`text_mask_prob=0`) vs. `meld_lora_textmask1` (`text_mask_prob=1`), both MELD, both carrying the identical `audio_tower` q/k/v LoRA treatment, differing only in supervision target — every stage moves only modestly while tracking triples (3/15→9/15): `audio_tower` +0.0132 (0.6035→0.6167), projector +0.0306 (0.5844→0.6150), final LLM layer +0.0368 (0.6439→0.6807), mid-stack peak (~layer 12-13) +0.014–0.020. This remains solid re-arbitration evidence for this one intervention — behavior shifts an order of magnitude more than any measured representation does — but it is 2 of an eventual 3 points on the MELD-only ladder, not a closed case: the decisive third point is `meld_lora_textmask1_acoustic` (`text_mask_prob=1.0` + acoustic-grounded CoT), still pending its own `extract_hidden_states.py` / `probe_accessibility.py` / `audio_ablation.py` run. If that point's probe AUC jumps sharply (e.g. toward LIME/ESD territory) while tracking only rises modestly further, the story would have to shift toward re-representation for *that* intervention specifically; if probe AUC stays near the other two MELD points while tracking rises again, re-arbitration holds across all three.

That third point has landed. `meld_lora_textmask1_acoustic` (`text_mask_prob=1.0` + acoustic-grounded CoT — the cell that layers acoustic-grounded supervision on top of `meld_lora_textmask1`'s already-total transcript removal) tracks at **9/15 on the same fixed donor-swap set — unchanged from `meld_lora_textmask1`**, not the 13 the gradient's prior slope would extrapolate to. Audio-only accuracy (`--audio-only`, same protocol): 0.535 (107/200), slightly below `meld_lora_textmask1`'s 0.573 — within a single 200-row run's ~3.4% SE, so read as flat/no-gain rather than a confirmed regression (the with-silence arm needed for this adapter's own audio-minus-silence delta is still pending). Both grounding measures agree there's no further movement: layering acoustic-grounded CoT on top of an already-fully-masked transcript adds nothing on MELD — the "replacement, not additive" reading already noted above for the partial-mask cell (acoustic CoT helped at `text_mask_prob=0.3`, 3/15→7/15) does not extend to the full-mask cell, where the transcript shortcut is already gone and there is nothing left for acoustic CoT to fix.

The probe profile matches "no further movement," with one wrinkle. `audio_tower` (0.6161) and `projector` (0.6125) are statistically indistinguishable from `meld_lora_textmask1`'s (0.6167 / 0.6150) — exactly the flat-control-point pattern re-arbitration predicts when tracking doesn't move. The final LLM layer, however, *drops* rather than holding flat: 0.6306, below not only `textmask1`'s 0.6807 but also below the collapsed baseline's 0.6439; the mid-stack peak both shrinks (0.7144 → 0.6978) and shifts later in the stack (layer ~12 → layer ~22). Since neither tracking nor accuracy rose, this dip isn't re-representation in the sense this probe is built to detect (rising AUC paired with rising behavior) — there's no behavioral rise here to explain. Read cautiously (one run, no replicate seed, and cross-validated AUC on 200 rows carries real fold-to-fold noise): one plausible account is that training the model to verbalize acoustic-cue claims it can't ground any more strongly than before (audio_tower/projector didn't change) displaces rather than adds to whatever audio-relevant signal reaches the final layer — a "taught to hallucinate acoustic detail" cost rather than a benefit. This is a hypothesis the data are consistent with, not one they establish; separating it from ordinary run-to-run variance needs a replicate (same config, different seed).

With this third point in hand, the MELD-only ladder closes the `text_mask_prob` axis specifically: the only step that moved tracking at all is baseline→textmask1 (transcript removal), where representation held flat while tracking tripled — clean re-arbitration. The second step (acoustic-grounded CoT layered on top) moved neither tracking nor representation in a way attributable to anything other than noise — it answers a supervision-redundancy question (already settled above), not the re-arbitration-vs-re-representation question this probe targets.

A fourth MELD-only point was added by running the same probe on `meld_lora_grounded` (`outputs/meld_lora_grounded/final`, `configs/train_config.yaml`: acoustic-grounded CoT + `text_mask_prob=0.3`, tracking 7/15 — the original supervision-level fix from the Core Finding, chronologically prior to and structurally distinct from the `text_mask_prob`-only ladder above: it changes both the CoT target *and* partially masks the transcript at once, where `textmask1` changes only the mask probability). Slotted into the corpus-held-constant MELD series by tracking (3→7→9→9), the `projector` stage — the one stage confirmed untrained at line 29 above — is not monotonic: 0.5895 (baseline) → **0.6441** (grounded) → 0.6143 (textmask1) → 0.6136 (textmask1-acoustic). The jump at the grounded point is real, not noise: baseline's and textmask1's `projector` AUC have each independently replicated within ~0.01 across three separate extraction runs (this run, the run behind the two-point ladder above, and the run behind the textmask1-acoustic addition), so a 0.05-point outlier at an intermediate tracking value sits well outside that band. The same adapter's layer-by-layer curve peaks higher than any other MELD adapter (0.727 at layer 21, vs. 0.698–0.717 for the other three) and decays by a comparable proportion to the final layer (0.639) — so `grounded` carries the richest mid-stack linear signal of any MELD checkpoint while tracking *behaviorally* lower (7/15) than `textmask1` (9/15). Read against `configs/train_config.yaml`'s `text_mask_prob: 0.3`: this adapter saw the transcript shortcut intact on 70% of training rows, so it was never forced to make audio decisive for the *final* label the way the fully-masked `textmask1` was — even while the acoustic-grounded CoT target (verbalizing real pitch/loudness/pace priors from `extract_acoustic_priors.py`) trained it to carry a more detailed acoustic representation mid-stack in order to produce that CoT text. This is a sharper version of "available but not accessible" than the flat-AUC reading above: not information present-then-discarded by depth alone, but information represented *more* richly while being *less* decisive for the behavior this study's ruler measures — a dissociation between CoT-driven representational richness and donor-swap-measured grounding. One run, no replicate seed, same caveat as the line-35 dip: a hypothesis the data are consistent with, not one they establish.

## Hypothesis

Modality collapse is gated by the presence of a transcript shortcut and by the decoder's training objective. Removing the shortcut at the data level — either by keeping the text present but uninformative about the label (a lexically-identical, multi-emotion corpus) or by removing it altogether (no transcript at all) — and counteracting it at the objective/architecture level (a dedicated emotion encoder with a disentanglement objective) are *distinct* mechanisms whose effects can be measured on a single, fixed ruler. Holding language constant, a coupled vs. decoupled comparison should reveal how much of the collapse is data-attributable vs. architecture-correctable.

## Approach: interventions measured on one ruler

The silence-vs-audio delta (and conflict-subset accuracy) is the fixed ruler across all conditions.

1. **Architecture/objective-level.** Add an emotion-centric encoder (Emotion2Vec / HuBERT) as a second tower beside the Whisper-style semantic path, with a modality-specific adapter and an orthogonality / disparity loss forcing the emotion tower to carry signal the semantic tower does not. Adapts the dual-encoder design of Zhang et al. (I2R/A\*STAR 2025) and the disentanglement losses of Chang et al. (IEEE JBHI 2026) to an audio-LLM.
2. **Data-level, a three-tier gradient.** Rather than a single coupled-vs-decoupled pair, the data-level intervention holds the silence-vs-audio ruler fixed across three corpora that vary only in how informative the transcript is about the label, from fully predictive to entirely absent:
   - **MELD** (coupled, the baseline above): transcript present and predictive — the shortcut this whole study is about.
   - **ESD** (primary decoupling condition). Kun Zhou, Berrak Sisman, Rui Liu, Haizhou Li (NUS/SUTD), "Emotional Voice Conversion: Theory, Databases and ESD," arXiv:2105.14762 (later in *Speech Communication*). 10 English + 10 Mandarin speakers, 350 parallel sentences read under each of 5 emotions (neutral/happy/angry/sad/surprise), ~17.5k English utterances; license-gated, research-only (`zhoukun@u.nus.edu`), downloaded directly via the Google Drive link in the dataset's own GitHub README (`HLTSingapore/Emotional-Speech-Data`), not via LIME's re-annotated version (LIME's re-annotation scripts are not public; see "Open premises"). Confirmed by direct read of the per-speaker transcript files (not just the paper's "350 parallel" prose): the *same exact sentence text* recurs under all 5 emotion labels for a given speaker, so the transcript is present but carries zero label signal by construction. Because the transcript is present, both halves of the ruler (audio+transcript and silence+transcript) can be run on ESD, exactly mirroring the MELD ablation — this is the property LIME Part B's public release claims but doesn't deliver (see below), and why ESD is the primary data-level corpus. ESD is run under both the plain (templated-CoT) and acoustic-grounded regimes used on MELD: the plain run isolates whether removing the transcript shortcut *at the data level alone* — leaving the CoT-from-gold-label shortcut diagnosed in the Core Finding otherwise untouched — already changes the silence-vs-audio delta, before the supervision-level fix is layered on top.
   - **LIME-Core Part B** (strictest supplement). English; `zhaoxiaoxian/LIME-440K_CogAudio-LLM` on Hugging Face; introduced in "Beyond Semantic Dominance: Cognitive Affective Reasoning and Empathetic Response Alignment in Audio Language Models" (Zhao, Wang, Tian, Hu, Zhang, Xie; ASLP@NPU; arXiv:2606.06940, accepted at INTERSPEECH 2026 per the arXiv listing). The paper frames Part B as "lexically-identical, multi-emotion" text, but the public release's `text` field is `null` for all ~96,000 records (see "Open premises"), so in practice it is a pure audio-only corpus with no transcript to leak at all — stricter decoupling than ESD's, but only the audio-only half of the ruler can be run on it; there is no transcript-present condition to compare against.

(A lighter supervision-level intervention — feature-anchored CoT targets computed from real acoustics plus transcript-masking — is already implemented and measured; see Core Finding above.)

## The controlled comparison (contribution)

The same dual-encoder + disentanglement architecture is run on **MELD** (natural speech, text-acoustic *coupled*, transcript shortcut available), **ESD** (acted speech, *decoupled* but transcript present — primary condition), and **LIME Part B** (synthetic speech, *decoupled*, no transcript at all — strictest supplementary condition) — all English, so language is held constant and coupling is the only manipulated variable across the gradient. This **directly tests the equivalence of data-level vs. objective-level interventions**: when the transcript shortcut is removed at the data level (in either of its two forms) versus counteracted at the architecture/objective level, does modality collapse change by the same amount, and does the *form* of data-level decoupling (uninformative-but-present vs. absent) matter? It supplies the systematic control that the cited works — each operating within a single data regime and testing one intervention family in isolation — do not provide.

## Open premises to verify (honest)

- LIME Part B's decoupling was originally taken from the paper as "lexically-identical text, multiple emotions"; a JSON-only probe (`scripts/probe_lime_partB.py`) was run instead to confirm this by direct read rather than by trusting the paper's prose. The Part A/B utterance counts (223,884 / 96,000) are confirmed via a direct read of the dataset card (`zhaoxiaoxian/LIME-440K_CogAudio-LLM`). The repo layout and field names are confirmed by a direct `HfApi.list_repo_files` + `json.load()` read (not the paper's prose, not the HF `datasets` auto-loader, which mis-parses this repo): annotations live under `PartA_json_CN/*.json` (Chinese) and `PartB_json_EN/*.json` (English, the split this project uses) as one JSON dict per file, keyed by utterance id, with fields `text`, `emotion`, `scenario`, `group`, `wav_path`; audio ships as one `PartB_wav_en.tar.gz` archive rather than per-row. The "both English" premise for the coupled-vs-decoupled comparison holds, since Part A/B are segregated by folder rather than mixed in one split.
  **Revised premise (probe result, exhaustive):** Part B's `text` field is `null` in 100% of its ~96,000 records in this public release — confirmed by scanning every one of the 32 `PartB_json_EN/*.json` files (`0 usable records, missing-field skips: 96000` when `text` was required) and by a full raw dump of one 3,000-record file showing every entry with `"text": null`. The `group`/`scenario`/`emotion`/`wav_path` structure is intact regardless: each `group` still contains multiple records with different emotions sharing one scenario, so LIME's "shared cluster, multiple emotions" design holds structurally even though the transcript itself is absent. This project therefore uses Part B as a **pure audio-only decoupling corpus** rather than a lexically-identical-text one: `scripts/build_lime_manifest.py` writes `transcript: ""` for these rows (no longer skipping them as missing-field), and `data/meld_dataset.py`'s `MELDDataset` forces `include_transcript=False` whenever a row's transcript is empty, independent of `text_mask_prob`. This is a strictly stronger decoupling condition than the original premise — there is no transcript at all to leak, lexically or otherwise, rather than a same-but-uninformative one. The punctuation-level nuance noted in an earlier draft of this bullet (e.g. the same sentence ending in "？！" for surprise, "......" for fear, "！" for happy) was observed in **Part A (Chinese)** samples, not Part B, and is reported here only as a caveat about Part A should it ever be used; it does not apply to the English Part B split this project trains/evals on, since Part B has no text to exhibit such a nuance in.
- **ESD's parallel-text structure**, confirmed by direct read of the extracted release (not the paper's prose alone): each speaker directory has one `<speaker_id>.txt` (tab-separated `utt_id`, `text`, `EmotionLabel`, 1,750 = 350×5 lines) plus 5 per-emotion `.wav` subfolders (`Neutral`/`Angry`/`Happy`/`Sad`/`Surprise`, 350 files each, matching the `.txt` labels exactly). For English speaker `0011`, utt ids `0011_000001` / `_000351` / `_000701` / `_001051` / `_001401` (an offset of exactly 350, the block size) all carry the literal text `"The nine the eggs, I keep."` under `Neutral`/`Angry`/`Happy`/`Sad`/`Surprise` respectively — the lexically-identical-text claim holds exactly, at least for this sampled case. Speakers `0001`–`0010` are Mandarin, `0011`–`0020` English (confirmed by reading `0001.txt`'s Chinese text vs. `0011.txt`'s English text), matching the dataset card. Audio is 16kHz mono PCM_16 already (confirmed via `soundfile.info` on a sampled file), so `scripts/build_esd_manifest.py`'s resample step is a no-op in practice but is kept as a defensive fallback. Release ships flat per-emotion folders with no train/evaluation/test subfolders (despite some secondary documentation describing a three-way split) — `build_esd_manifest.py` does its own group-level split, grouping by `(speaker, sentence-index)` derived from the utt-id numbering, to keep a sentence's 5 emotion-variants from spanning train and dev.
- LIME is TTS-synthesized; ESD is studio-recorded but acted/read speech, not spontaneous — in both cases a residual synthetic-or-acted vs. spontaneous prosody gap relative to MELD's natural speech is a known limitation, reported rather than hidden.
- The two framing citations (arXiv 2505.22483, 2602.23136) are now corroborated by independent search of their arXiv/ICML listing pages — titles, authors, venue, and core claims all match the prose above, no longer flagged. The one open item is the specific **+7.5% modal-accessibility** figure attributed to arXiv 2602.23136: a search summary did not surface that exact number, so it still needs a direct read of the paper text before submission. (The LIME-440K citation, arXiv 2606.06940, is confirmed directly from the arXiv listing page itself, author list and INTERSPEECH 2026 acceptance included.)

## Expected Contribution

Not beating SOTA on emotion accuracy. Rather: a clean, reproducible, single-GPU study that (1) measures modality collapse on a fixed ablation ruler, (2) applies mechanistically distinct interventions, and (3) compares coupled vs. decoupled speech under one language to directly test whether data-level and objective-level interventions are equivalent — a control absent from prior work, each of which establishes one intervention in isolation. Every claim ties to a re-runnable ablation rather than to the cited papers.

## Success Criterion

For each condition, re-running the silence-vs-audio ablation yields a measurable, reported shift; the coupled-vs-decoupled contrast yields an interpretable difference in collapse magnitude. A partial outcome on natural MELD (collapse reduced, not eliminated) is a valid result and the stated motivation for data-level decoupling.

## Future Work

Isolate whether ESD's stronger acoustics add anything *on top of* decoupling (Core Finding, the `text_mask_prob=1.0` paragraph) rather than reading it off a cross-corpus comparison (MELD `text_mask_prob=1.0` vs. ESD-plain) that confounds corpus, acoustic strength, and CoT regime at once. Needs a same-corpus acoustic-strength manipulation holding decoupling and CoT regime fixed — e.g. a tertile-matched within-ESD comparison, or synthetic loudness/pitch-variance augmentation applied to MELD clips — not a corpus swap.

A planned LoRA-placement attribution experiment — train Audio-LoRA-only, LLM-LoRA-only, and Both arms on the same MELD corpus, to causally separate "is the information present" from "who is responsible for using it" — needs a `target_modules` fix before it can run cleanly. Per the Core Finding correction above, every adapter trained so far under `configs/lora_config.yaml` is already a (lopsided) Both condition, not the LLM-only baseline it was assumed to be. PEFT 0.19.1 matches a *string*-valued `target_modules`/`exclude_modules` via `re.fullmatch` against the full dotted module path (`peft/utils/other.py::match_target_against_key`), unlike the per-component suffix match used for *list*-valued ones — so a clean split needs path-qualified regex strings, not bare component names: `"model\.language_model\..*\.(q_proj|k_proj|v_proj|o_proj)$"` for the LLM-only arm, `"model\.audio_tower\..*\.(q_proj|k_proj|v_proj|out_proj)$"` for the audio-only arm (path confirmed via `Qwen2AudioForConditionalGeneration.model.{audio_tower,language_model}`), and the union of both for Both. Worth a one-line `for n, _ in model.named_modules(): print(n)` sanity check against the real loaded checkpoint before committing to these patterns, rather than trusting this derivation blindly.

The same evidence-grounded CoT mechanism — a model that states the acoustic cues behind its emotion judgment — could serve as a case-level interpretable layer atop existing classical pipelines in clinical speech assessment, complementing rather than competing with feature-based methods. Pursuing this in a UHR / clinical setting would require not only data access and ethics approval but genuine domain grounding in the clinical construct, which is a prerequisite to be built, not an asset already in hand. Out of scope here.

## Environment

All training/inference on the GPU cluster (H100). Login/transfer node for downloads (compute nodes offline). `$HOME` (`/`) is a small, easily-filled 58 GB partition — confirmed the hard way when it hit 100%/0 available mid-download. All large data (LIME's 52 GB audio, ESD's ~2.45 GB, HF/conda/pip caches via `HF_HOME`) goes on the shared `/data` volume (3+ TB, confirmed via `df -h`) instead, e.g. `/data/user_dirs/$USER/`; there is no `$SCRATCH` env var set on this cluster, despite some earlier guidance assuming one.

The per-student GPU allocation turned out to be a MIG (Multi-Instance GPU) slice, not the full card: `nvidia-smi` shows the physical device as an `H100 80GB HBM3` with MIG enabled, partitioned into seven `1g.10gb` instances (~9.75 GiB each), and the student's job is bound to exactly one such slice with no contention from other processes ("No running processes found" on the others). Qwen2-Audio-7B-Instruct (~8.2B params) needs ~16 GB just for bf16 weights, so `Qwen2AudioForConditionalGeneration.from_pretrained(..., torch_dtype=torch.bfloat16)` OOMs inside `from_pretrained` itself, before any batch-size/gradient-accumulation tuning or training data is even touched — confirmed by identical `torch.OutOfMemoryError` traces on both the ESD smoke test and the full ESD plain-baseline run, both failing at the same "Loading weights" checkpoint. Fix: load the base model 4-bit-quantized (QLoRA-style: `BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_use_double_quant=True, bnb_4bit_compute_dtype=torch.bfloat16)`), bringing base weights to ~4 GB and leaving headroom for activations and the LoRA adapter within the 9.75 GiB slice. Centralized in `data/model_loading.py::load_base_model`, used by all five scripts that load the base model.

A second, narrower OOM showed up one step later, only in `train_lora.py`: `peft.prepare_model_for_kbit_training()` (the standard pre-LoRA call on a quantized base) casts every bf16/fp16 param that ISN'T 4-bit-quantized -- embeddings, lm_head, norms -- to fp32, and that cast itself OOM'd (~8.5 GiB already in use right after the 4-bit load, then a 2.38 GiB fp32-upcast allocation that didn't fit in the remaining ~1.26 GiB). Since the base model is frozen regardless (LoRA only trains the adapter) and `bnb_4bit_compute_dtype=bfloat16` already runs every matmul in bf16 independent of storage dtype, the fp32 upcast buys stability headroom this slice can't afford and doesn't need. Replaced with `data/model_loading.py::prepare_for_qlora_training`, which keeps the two things that matter under this memory budget -- `enable_input_require_grads()` and `gradient_checkpointing_enable()` -- without the upcast. Confirmed working end-to-end on the real 9.75 GiB slice: the ESD smoke test (`train_config_esd_smoke.yaml`) completed all 10 steps of its single epoch with loss falling 3.59 -> 1.41, no OOM at load, prepare, or any training step.

Hardware-mismatch, now confirmed (was an open question): the MELD Core Finding numbers (0.645 / 0.670, plain bf16, no quantization) were produced on the **full 80 GB card**, not a MIG slice — consistent with the fact that bf16 weights (~16 GB) cannot fit the 9.75 GiB `1g.10gb` slice at all. Every subsequent run (ESD plain, and any MELD rerun) is on the **10 GB MIG slice in 4-bit QLoRA**. So the original baseline and the new runs differ on *two* axes at once — hardware (full card vs. 1/7 slice) and numerical precision (bf16 vs. 4-bit nf4) — and are **not directly comparable** until that gap is measured. The hardware axis doesn't change the *model's* accuracy (a 200-row greedy eval is deterministic regardless of which GPU runs it), but the **precision axis can**: 4-bit quantization of the base weights could shift accuracy and, more importantly for this study, could shift how much the model leans on the audio. The immediate next training run therefore re-runs the **MELD baseline under 4-bit QLoRA** on the same fixed ablation ruler, to quantify the bf16→4-bit delta directly and decide whether the original 0.645 / 0.670 numbers can stand as the comparison anchor or must be replaced with a quantized re-baseline. The `text_mask_prob=1.0` confound-breaking cell (above) is gated on this: it needs a same-precision baseline to compare against.

The 4-bit MELD plain-baseline rerun (`configs/train_config_meld_plain_4bit.yaml`, `outputs/meld_lora_4bit/final`) resolves the question above. Same 200-row dev sample, same greedy decoding, same fixed 15-row donor-swap index set as the bf16 baseline: audio + transcript = 0.660 (132/200, vs. bf16's 0.645); silence + transcript = 0.655 (131/200, vs. 0.670); audio + placeholder transcript = 0.515 (103/200, identical to bf16's 0.515); donor-swap tracking = 3/15 (vs. 2/15). The audio − silence delta flips sign relative to bf16 (−0.025 → +0.005), but at n=200 the standard error on a single accuracy point is ~3.4%, so a 0.005 shift is noise rather than a directional change; the donor-swap difference (2/15 vs. 3/15) is likewise within the noise of a 15-row sample. Per the runbook's own read-out criterion, neither the delta nor the tracking ratio moved materially, so 4-bit quantization preserves the collapse pattern rather than confounding it: **the bf16 anchor (0.645 / 0.670 / 0.515, 2/15) stands as the comparison baseline for the `text_mask_prob=1.0` and ESD-acoustic-grounded cells**, and no quantized re-baseline is needed.

The wall-clock cost of fitting on a `1g.10gb` slice is structural, not a misconfiguration: MIG partitions compute (SM count) and memory bandwidth proportionally to memory capacity, so this slice has roughly 1/7 of the card's compute regardless of how much of its 9.75 GiB is actually used. On top of that, the two OOM fixes above are both time-for-memory trades that add real overhead beyond the 1/7 split: `gradient_checkpointing_enable()` recomputes the forward pass during backward instead of caching activations (the dominant slowdown), and 4-bit weights must be dequantized to bf16 before every matmul. `per_device_train_batch_size: 2` also leaves per-step GPU parallelism underused. None of these are tunable away without more memory headroom than this slice has (~2 GiB free during the ESD plain run at 7952/9984 MiB used) — there isn't room to disable checkpointing, and raising `gradient_accumulation_steps` doesn't help wall-clock since it changes how often `optimizer.step()` runs, not the per-micro-batch compute (the actual fix, raising `per_device_train_batch_size`, would need more memory, the opposite of what's available). TF32 (`torch.backends.cuda.matmul.allow_tf32` / `cudnn.allow_tf32`, set at import in `data/model_loading.py`) is the one free lever — no memory cost, since the 4-bit matmuls already run in `bnb_4bit_compute_dtype=bf16` regardless and TF32 only affects the remaining fp32 paths (LoRA adapter, unquantized embeddings/lm_head/norms).

Every `train_lora.py` run now writes `<output_dir>/run_metadata.jsonl` (one line per process launch: resolved config, LoRA config, resume source, start time) and `<output_dir>/metrics.jsonl` (one line per `logging_steps` interval: step, epoch, loss, lr, wall-clock elapsed) — durable records of what a run was and how it went, independent of terminal/tmux scrollback. Added after a run produced no record of its own hyperparameters or loss trajectory once the shell history scrolled past it.
