# 业务价值分析(Business case)

> 数字都由 `scripts/generate_docs.py` 从 `results/benchmark.json` 填入,不手写。人工耗时和成本是空白,写作 `TBD — 人工基线`,需要由使用者实测后填写,这里不估计。

## 1. 要解决的问题

判断两个蛋白如何结合,需要把结构库、序列库、模拟数据和文献放在一起对照。证据常常互相矛盾(本项目的案例 FAT10–MAD2:MD 界面在 C 端,文献/NMR 预期在 N 端 UBL1 结构域),而且没有实验复合物结构可以当标准答案。核心风险不是"查得慢",而是**引用了不存在或对不上的数据,或者把矛盾说成有定论**。

## 2. 人工流程 vs agent 流程

| 步骤 | 人工流程 | agent 流程 |
|---|---|---|
| 确认体系 | 在 PDBe / UniProt 网页上手动查条目、序列、结构域 | 工具现查 PDBe(MCP 查询,失败时退回已核实快照)和 UniProt |
| 读文献 | 在 PubMed 检索,逐篇读摘要,自己摘出结合区域 | 工具检索 PubMed,agent 读摘要;检索不到时标注为"引用",不假装检索过 |
| 取模拟证据 | 从模拟输出里自己算接触占有率 | 直接读取已生成的真实接触占有率文件;没有数据就报告"待定" |
| 核对残基编号 | 手动对照序列,容易漏 | `validate_residues` 逐个核对 UniProt 序列,对不上就标记 |
| 比对与判断 | 自己比较 MD 界面和文献区域 | 确定性检查给出矛盾标记;冲突时开辩论,给出谨慎结论 |
| 输出 | 自己写报告和引用 | 带完整工具调用记录的报告;标注真实 / 引用 / 待定 |
| 人的角色 | 全程执行 | 提问、审阅、决定做什么验证实验 |

agent 不替代实验,也不宣布哪一方正确;它把"收集与对照证据、发现矛盾"这部分重复劳动自动化,并保留可复查的记录。

## 4. 风险与应对

| 风险 | 说明 | 应对措施(现状) |
|---|---|---|
| 编造数据 | 语言模型可能编造残基、分数或文献 | 所有数值只来自工具;无数据的工具报告"待定";`validate_residues` 核对序列;报告保留完整工具调用记录 |
| 错误输入未被发现 | 错误注入测试显示,编号偏移、越界、编造的残基身份、错误的 UniProt 号能被序列核对拦截;**只改数值、不改残基标签的伪造 MD 分数无法被序列核对发现** | 已如实记录在评估报告里;后续需要给 MD 分数文件加来源校验(如校验和、生成脚本记录),目前**尚未实现** |
| 把矛盾说成有定论 | 没有实验复合物结构时,任何一方都不是标准答案 | 提示词和法官角色要求只报告矛盾、不判定胜负,并建议验证实验;有测试固定这一措辞 |
| 基准评估偏乐观或不稳定 | 案例少;模型可能背过经典复合物;UniProt 特征表本身来自历史文献 | 无工具基线并列展示;泄露过滤(同一对蛋白的所有复合物结构与对应论文都不给 agent);报告写明样本小、只作趋势 |
| 答案泄露 | agent 看到同一对蛋白的实验复合物或论文 | 结构和文献过滤、输出守卫、基准运行中丢弃不在工具模式里的参数;仍有残余风险(综述文字、含模拟配体的其他结构),见 `docs/benchmark_design.md` |
| 外部服务不可用 | PDBe / UniProt / PubMed / DeepSeek 可能超时或限流 | 失败被如实记录为失败或"无法判定",不会被当作成功;PDBe 有已核实快照兜底(仅 FAT10) |
| 费用失控 | 深入调查和辩论调用外部模型,反复触发会持续产生费用 | 限制最大步数;运行日志记录每次成本;API 本身没有限流和身份验证,公开部署前需要加反向代理与密钥(见 `docs/dify_setup.md`) |
| API 被未授权访问 | 服务本身没有身份验证 | 默认只对本机开放;公网访问必须经过带密钥的代理;只读端点可单独放行 |
| 价格信息过期 | 成本依赖第三方价格表 | `config/pricing.yaml` 记录核对日期与来源;正式使用前核对官方价格 |
| 单次 MD 的局限 | 案例只有一条 MD 轨迹,界面反映 AF3 起始构象 | 在 README 中明确写为"对该模型的一致性检查,不是独立验证" |
| Dify 接入未在真实环境验证 | 接入文档未在某个具体 Dify 版本上逐步实测 | 文档中已注明;上线前需要人工走一遍 |
